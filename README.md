# ROMEO OS — рабочее демо

Единый интерфейс управления цветочной сетью: показатели восьми магазинов, финансовые отчёты, заявки на расходы, задачи и помощник. Интерфейс построен вокруг ежедневной работы собственника: три основных показателя, очередь заявок с прямым переходом к решению и сравнение магазинов. Единая визуальная система использует Montserrat, белый фон, нейтральные серые границы и контрастный текст. На компьютере разделы доступны в боковом меню, на телефоне — в нижней навигации. Вкладки используются внутри разделов.

Повторяющиеся пояснения и плашки убраны с рабочих экранов. Информация о тестовых данных, отсутствии подключений и ролевом просмотре доступна через **Помощь**; выгружаемые CSV сохраняют маркировку «ДЕМО-ДАННЫЕ».

**Все данные, магазины, адреса и сотрудники вымышлены.** Подключений к реальным аккаунтам МойСклад, банкам и внешним ИИ-моделям нет. Никакие реальные платежи не выполняются.

## Как открыть демо и дать доступ Азату

Для просмотра по ссылке используется GitHub Pages. Ветка `gh-pages` содержит готовый сайт с вымышленными данными. Регистрация в демо не требуется; роли переключаются внутри интерфейса. Ссылка будет публичной, поэтому реальные финансовые и клиентские данные в эту версию добавлять нельзя.

Если Pages ещё не включён, владелец репозитория один раз открывает [Settings → Pages](https://github.com/zhantugelmukagali/romeo-oc-test/settings/pages) и выбирает:

1. **Source:** Deploy from a branch.
2. **Branch:** `gh-pages`, папка **/(root)**.
3. **Save.** Дождаться успешного `pages build and deployment` в GitHub Actions.

Адрес после успешного развёртывания: **https://zhantugelmukagali.github.io/romeo-oc-test/**. Этот адрес можно отправить Азату; аккаунт GitHub для просмотра публичного сайта не нужен. Само наличие ветки не подтверждает, что Pages включён или сайт уже работает.

Изменения каждого посетителя сохраняются только в его браузере. Это демонстрация, а не общая многопользовательская база. Чтобы начать показ заново, используйте **Настройки → Сбросить изменения**.

Для обновления сайта после изменений:

```bash
# Сначала проверить и закоммитить изменения в main.
npm run deploy:demo
```

Команда собирает один HTML и отправляет его в `gh-pages` обычным push без принудительной перезаписи. Существующие пользовательские файлы в этой ветке блокируют публикацию, чтобы случайно их не удалить. Включение Pages — отдельная настройка GitHub.

Без хостинга можно [скачать HTML из ветки gh-pages](https://github.com/zhantugelmukagali/romeo-oc-test/raw/refs/heads/gh-pages/index.html), переименовать в `ROMEO-OS-demo.html` и открыть на компьютере в браузере. Этот же файл можно передать Азату. На мобильном устройстве удобнее использовать сайт.

## Быстрый запуск

Проверено с Node.js 24 и npm 11. Для Vite нужен Node.js 20.19+ или 22.12+; для запуска TypeScript-тестов без дополнительных инструментов используйте Node.js 24.

```bash
cd /workspace/romeo-oc-test
npm ci --cache /tmp/romeo-npm-cache
npm run dev
```

Vite использует порт 5173. Для обычного размещения статического сайта:

```bash
npm run build
npm run preview
```

Готовые файлы сайта находятся в `dist/`. Их можно размещать на статическом хостинге; сервер приложения демо не требуется.

## Один HTML-файл для показа

```bash
npm run build:demo
```

Результат — `demo-dist/index.html`. Скопируйте этот файл на свой компьютер и откройте в современном браузере. Скрипты, стили и шрифты встроены; Интернет и установка Node.js для показа не нужны. Для отправки можно переименовать в `ROMEO-OS-demo.html`.

Заявки, задачи, настройки компании и состояния демо-подключений сохраняются в localStorage этого браузера. Хранение для `file://` зависит от браузера; для постоянного использования предпочтителен статический хостинг. Если сохранение запрещено настройками браузера, текущая сессия продолжает работать, но изменения могут не пережить перезагрузку.

## Сценарий встречи с Азатом — 5–7 минут

1. **Обзор сети.** Покажите выручку, предварительную прибыль и деньги. Выберите магазин «Ботанический», затем другую длительность периода. Графики и показатели пересчитываются из общего набора данных.
2. **Финансы → Прибыль и убытки.** Пройдите путь от выручки через себестоимость и расходы к управленческому результату. Покажите предупреждение о незакрытом периоде.
3. **Движение денег.** Откройте операцию: сумма, магазин, статья, дата и источник. Найдите аренду через поиск. Скачайте CSV.
4. **Заявки.** Создайте расход или откройте «Сервис холодильной камеры», согласуйте либо отклоните. Согласование не меняет ДДС, поскольку платёж ещё не проведён.
5. **Помощник.** Спросите «Сравни магазины по прибыли» или «Сколько денег осталось?». Покажите расчёт и источник. Это демонстрация сценария будущего ИИ, использующая фиксированный набор правил.
6. **Профиль справа сверху → Сменить роль.** Управляющему доступны показатели одного магазина и создание заявок; согласование недоступно. Сотруднику доступны только собственные задачи и инструкции. История помощника очищается при смене роли, магазина или периода.
7. **Задачи.** Примите задачу в работу и завершите её. Изменения сохранятся после перезагрузки браузера.

8. **Настройки.** Измените название и аватар, выключите уведомления, выберите часовой пояс и сохраните. Изменения применяются к интерфейсу и переживают перезагрузку.
9. **Настройки → Интеграции.** Запустите проверку источника, дождитесь результата, затем повторите её или сбросьте статус. Все стадии симулируются локально; настоящих API-запросов нет.

Перед следующим показом: **Настройки → Сбросить изменения → Восстановить**.

## Что работает

- Единый детерминированный набор за 1 августа — 31 октября 2026, восемь магазинов.
- Фильтрация по доступному магазину и периоду, сравнение с предыдущим периодом. Для квартального диапазона предыдущие данные отсутствуют, сравнение не показывается.
- P&L: выручка, себестоимость, валовая прибыль, зарплаты, аренда, эквайринг, списания и прочие расходы.
- ДДС: начальный остаток, поступления, выплаты, конечный остаток, поиск и детализация операций, пагинация, CSV.
- Создание, согласование и отклонение расходных заявок; сохранение в браузере.
- Создание задач, выбор ответственного и срока, переходы между статусами; сохранение в браузере.
- Четыре демо-роли; фильтры интерфейса и ограничения сценариев помощника.
- Помощник: продажи, средний чек, расходы, прибыль, ДДС, сравнение магазинов, текущие заявки, инструкция по списанию.
- Глобальный поиск по разделам, магазинам, задачам и заявкам; уведомления; мобильная навигация.
- Раздел, магазин, период и вкладка финансов сохраняются в адресе; работают обновление страницы и кнопки браузера «Назад»/«Вперёд». Выбранная демо-роль сохраняется в текущей вкладке браузера.
- Кнопка «Создать» открывает заявку или задачу из любого раздела. После сохранения виден созданный объект; неподходящие фильтры автоматически сбрасываются.
- На главной — сами ожидающие заявки с магазином, автором и суммой. Их можно открыть и согласовать прямо из обзора. Дублирующие сводки команды и промоблок помощника убраны.
- Решение по заявке и смену статуса задачи можно отменить через уведомление в течение 10 секунд, до следующего уведомления. Закрытие заполненной формы через крестик, Escape или фон требует подтверждения.
- Черновик настроек сохраняется в текущей вкладке при переходах и обновлении страницы. Применение изменений — по кнопке «Сохранить настройки»; сброс демо удаляет и черновики.
- Магазины представлены одной сравнительной таблицей, задачи — рабочим списком по статусам. Формы создания открываются в боковой панели, на телефоне занимают весь экран.
- На телефоне заявки и денежные операции представлены вертикальными списками с явными действиями.
- Сохраняемые настройки, переключатель уведомлений, выбор аватара и часового пояса.
- Проверка сценария подключения источников с прогрессом, результатом, отменой и сбросом. Внешние API не вызываются; успешный результат отмечается как «Проверено».
- Montserrat встроен в приложение, включая кириллицу. Одинаковый шрифт используется в заголовках, формах, кнопках, таблицах и графиках; внешних запросов при работе демо нет.

## Финансовая модель

Выручка и расходы начисляются по дням. Аренда и зарплата распределяются по календарным дням месяца, а выплаты в ДДС отражаются в конкретные даты. Себестоимость проданного товара отличается от оплаты поставщикам. Поэтому прибыль и денежный поток не совпадают.

Управленческая прибыль в демо = выручка − себестоимость − зарплаты − аренда − эквайринг − списания − прочие расходы. **Налоги и общесетевые расходы не моделируются; результат не является чистой прибылью.** Денежные операции агрегированы по дням и магазинам, а не являются реальными первичными банковскими документами.

Денежный остаток на 1 августа составляет 1 500 000 ₸ на магазин. Последующие начальные и конечные остатки непрерывно рассчитываются по операциям. Согласованные заявки не участвуют в ДДС и P&L до проведения операции, которого в этом демо нет.

## Ограничения перед внедрением

- Роли переключаются для показа. Это **не настоящая авторизация**: весь вымышленный набор находится в клиентском коде. Настоящие данные потребуют серверной проверки прав, изоляции магазинов и аудита действий.
- Нужны сервер, база данных, безопасное хранение секретов и коннекторы МойСклад/финансовых источников. API-ключи не должны попадать в браузер.
- Нужны первичная загрузка, обработка изменений и удалений, повторы без дублей, мониторинг и сверка.
- Бизнес должен подтвердить формулы, состав расходов, правила закрытия периода и права согласования.
- Помощник реализован правилами, без LLM и RAG. Для свободных вопросов потребуется подключение модели к проверенным функциям расчёта и базе согласованных регламентов.
- Логистика и маркетинговые функции исключены из текущего объёма.

## Проверки

```bash
npm test
npm run build
npm run build:demo
```

`npm test` проверяет сверку финансов, периоды, доступы, ответы помощника и восстановление контекста из адреса.

Браузерные проверки используют Python Playwright и установленный `/usr/bin/chromium`. В текущей облачной среде они уже доступны. При необходимости в другой среде установите Playwright и Chromium отдельно, сохраняя проверку TLS.

```bash
# В отдельном терминале должен работать npm run dev.
python tests/smoke.py
python tests/interactions.py
python tests/ux.py
python tests/layout.py
# Проверка переносимой сборки: в отдельном терминале запустите
# python -m http.server 4174 --bind 127.0.0.1 --directory demo-dist
ROMEO_TEST_URL=http://127.0.0.1:4174 python tests/smoke.py
ROMEO_TEST_URL=http://127.0.0.1:4174 python tests/ux.py
```

Управляемый Chromium в этой среде запрещает открытие `file://`; переносимая сборка проверяется через локальную статическую раздачу без внешних запросов. Открытие файла напрямую в обычном браузере пользователя зависит от его локальных политик.

Проверяются фильтры, выгрузка, операции, создание/сохранение/согласование заявки, задачи, помощник, ограничения ролей, уведомления, поиск, сброс, мобильный экран и ошибки JavaScript. Скриншоты создаются вне репозитория в `/tmp/romeo-demo-checks` (путь можно изменить через `ROMEO_TEST_ARTIFACTS`).

## Структура

- `src/data.ts` — демонстрационные данные, финансовые расчёты, ограничения ролей и сценарии помощника.
- `src/App.tsx` — разделы и рабочие процессы.
- `src/navigation.ts` — адреса разделов, история браузера и допустимый контекст каждой роли.
- `src/ui.tsx` — графики, диалоги, фильтры и выгрузка.
- `src/SettingsPage.tsx` — настройки пространства, доступы и интерактивные демо-подключения.
- `src/design-system.css` — единые стили, типографика Montserrat, компоновка экранов и адаптивность.
- `.github/workflows/check.yml` — проверка и сборка сайта и переносимого HTML в GitHub Actions.
- `tests/` — проверки бизнес-логики и браузерных сценариев.

В облачных задачах используйте существующий checkout `/workspace/romeo-oc-test`: среда уже изолирована; отдельный Git worktree без явного запроса не нужен.
